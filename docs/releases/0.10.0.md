# Assegai Auth 0.10.0

Assegai Auth 0.10.0 completes the documented session-login workflow for the AssegaiPHP 0.10 milestone.

## Session login documentation

The new end-to-end guide covers:

- application-owned user lookup
- username and password-field configuration
- password verification through `SessionAuthStrategy`
- session establishment and identifier rotation
- sanitizing the stored user
- a Core session guard that produces `UnauthorizedException`
- the opt-in, application-configured `LoginRedirectFilter`
- login and logout redirects
- safe intended-target restoration with `Session::pull()`
- normal API 401 behavior when the redirect filter is not applied
- the boundary between standalone strategy session options and Core-owned framework sessions

See [Session Login End to End](../session-login.md).

## Runtime compatibility

This milestone does not change Auth's runtime strategy APIs. The existing session, JWT, and OAuth tests remain the release gate. Applications using Core 0.10 should place non-secret redirect and framework-session policy in `config/auth.php`; standalone applications continue to configure `session_name` and `session_lifetime` on `SessionAuthStrategy` when needed.
